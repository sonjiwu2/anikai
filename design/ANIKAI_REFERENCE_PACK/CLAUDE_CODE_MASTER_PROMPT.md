# ANIKAI — мастер-промпт для Claude Code

Ты — опытный frontend-разработчик и продуктовый UX/UI-дизайнер. Реализуй законченный, красивый, интерактивный многостраничный аниме-видеосервис **Anikai** по приложенным референсам. Работай как над собственным продуктом для реальных пользователей: качество композиции, удобство, адаптивность, изображения, поведение компонентов и техническая надёжность одинаково важны.

Нужно создать работающий frontend, который приятно открывать на телефоне, планшете и ПК. Доведи реализацию до проверенного результата. Не заканчивай после плана, установки зависимостей, первой страницы или набора визуальных заглушек. Продолжай реализацию, запуск, проверку и исправления, пока критерии приёмки ниже не выполнены. Если появляется реальное ограничение среды, сообщи конкретно о нём и сделай всё остальное, что возможно.

## 2. Цель и границы продукта

Создай статически размещаемое frontend-приложение без собственного backend, базы данных, server actions, обязательной авторизации и обязательных платных API. Страницы, фильтры и интерактив работают в браузере. Данные каталога — локальные типизированные файлы. Коллекция, история, профиль, настройки и списки — локальные данные браузера.

Для первой версии достаточно каталога из 18–24 настоящих аниме. В нём должны быть как минимум Дандадан, Фрирен, Магическая битва, Человек-бензопила, Клинок, рассекающий демонов, Семья шпиона, Атака титанов, Тетрадь смерти, Ван-Пис, Волейбол!!, Монолог фармацевта, Поднятие уровня в одиночку. Точность состава и данных важнее заполнения до искусственного большого числа.

Основные функции: поиск, каталог, фильтры, страница аниме, выбор серии, настоящий видеоплеер, продолжение просмотра, личная коллекция, пользовательские списки, история, календарь, профиль, настройки, импорт и экспорт данных. Видимые кнопки должны выполнять понятное действие.

Не добавляй ради масштаба подписку, оплату, административную панель, социальную сеть, публичные аккаунты и серверную систему комментариев. Личный профиль — локальный, а не настоящий аккаунт с паролем.

Публичные обсуждения на референсе плеера — пример композиции. В frontend-only реализации замени их качественным блоком **«Мои заметки к серии»**: заметка, таймкод, редактирование и удаление. Нажатие на таймкод перематывает видео. Не показывай выдуманную активную аудиторию и не обещай публикацию комментария другим пользователям.

## 3. Технологии и архитектура

Если проект пустой, базовый выбор: React + TypeScript + Vite. Используй React Router в клиентском режиме. Для стилей выбери один последовательный подход: CSS Modules/обычный CSS с токенами или Tailwind с совместимым актуальным Vite-плагином. Для иконок подойдёт единая библиотека вроде Lucide либо небольшой собственный SVG-набор. Не смешивай несколько иконочных систем.

Перед установкой проверь совместимость актуальных стабильных версий, доступную версию Node и официальную документацию. Не смешивай инструкции разных основных версий React Router/Tailwind. Если стек уже настроен, не переписывай его только ради другого инструмента. Не выбирай серверный фреймворк для задачи, которой достаточно статического frontend.

Организуй проект по ответственности: страницы, общие UI-компоненты, каталог/коллекция/плеер, типы, данные, локальное хранилище, стили и утилиты. Не помещай приложение в один гигантский файл. Не усложняй архитектуру абстракциями без реального применения.

Нужны повторно используемые компоненты: AppShell, Header, MobileNav, AnimePosterCard, ContinueWatchingCard, EpisodeCard, SearchDialog, FilterPanel, Tabs, Select, Dialog/BottomSheet, Toggle, Toast, EmptyState, VideoPlayer. Названия можно изменить, сохранив смысл.

Не допускай TypeScript `any` там, где тип очевиден. Производные значения вычисляй из данных, а не дублируй в нескольких состояниях. Обработчики событий и подписки очищай при размонтировании. Запись состояния плеера ограничивай по частоте. Не добавляй библиотеку для каждой маленькой функции.

## 4. Маршруты и навигация

Реализуй отдельные маршруты:

- `/` — главная;
- `/catalog` — каталог;
- `/schedule` — расписание;
- `/collection` — коллекция;
- `/anime/:slug` — страница аниме;
- `/watch/:slug/:episodeId` — просмотр;
- `/profile` — обзор профиля;
- `/profile/history` — полная история;
- `/settings` и при необходимости подразделы — настройки;
- `/collection/list/:listId` — пользовательский список;
- понятная 404 для неизвестных страниц.

У страницы аниме есть вкладки «Серии», «Об аниме», «Мои заметки», «Похожее». Активную вкладку можно хранить в URL query или вложенном маршруте. Фильтры каталога, поиск, сортировку и номер страницы сохраняй в query-параметрах, чтобы назад/вперёд и копирование URL работали ожидаемо.

На хостинге с SPA fallback используй обычные чистые пути. Если целевой статический хостинг не поддерживает rewrite, документируй fallback или используй подходящий hash routing. Не оставляй прямые ссылки сломанными при обновлении страницы.

Все переходы — через правильные ссылки/роутер, без полной перезагрузки приложения. Активный раздел соответствует текущему экрану. Страница аниме и просмотр относятся к каталогу, а не к «Главной». При переходах обновляй document.title, корректно управляй скроллом и фокусом. Названия: «Каталог — Anikai», «Фрирен — Anikai» и т. п.

## 5. Визуальное направление

Главный источник стиля — `01_home.png`. Сохрани спокойный графитовый фон, чистый гротеск, мягкий синий акцент, узнаваемые аниме-обложки и тонкие контурные иконки. Визуальный характер — зрелый медиасервис, а не игровой HUD и не SaaS-дашборд.

Начальные токены:

```css
--bg: #121318;
--surface: #1B1D24;
--surface-raised: #252832;
--text: #F4F3EF;
--text-muted: #A2A6B1;
--accent: #819BFF;
--accent-hover: #96ACFF;
--border: rgba(255, 255, 255, 0.10);
--radius-card: 10px;
--radius-control: 8px;
```

Проверь реальные контрасты. Не сохраняй токен, если из-за него становится нечитаемым текст. Для кнопки с синим фоном используй тёмный текст и иконку. Зелёных и лаймовых элементов интерфейса не должно быть, включая статусы успеха: успех обозначай синей/нейтральной иконкой и текстом. Цвета самих канонических персонажей не перекрашивай.

Не используй serif, кислотное свечение, повсеместное стекло, тяжёлые градиенты, emoji вместо иконок, огромные радиусы и бездумные цветные плашки. Сдержанные тени допустимы для меню и модальных слоёв. Не выводи размеры, технологии, localStorage или другие внутренние детали на главную страницу.

Используй один качественный шрифт с хорошей кириллицей, например Inter, и системный fallback. По возможности размести шрифт локально. Обычный текст 14–16px; критичный интерфейс не меньше 14px; вторичная метаинформация может быть 12–13px при достаточном контрасте. Кегль страницы обычно 28–36px desktop и 24–30px mobile. Заголовок hero допускает 40–56px desktop и 28–36px mobile. Не делай все заголовки одинаково огромными.

Сетка отступов 4/8px: 8, 12, 16, 20, 24, 32, 40, 48. Desktop content max-width около 1440px плюс внешние отступы; на очень широком мониторе содержимое не растягивается без ограничений. Desktop gutters 32–48px, tablet 24px, phone 16px. Значения можно тонко скорректировать после визуальной проверки, не разрушая ритм.

Кнопки 40–44px desktop, целевые области касания минимум 44x44px mobile. Все состояния hover/focus/pressed/selected/disabled продуманы. Минимальная высота основных полей 44px. Тонкая синяя линия для активной вкладки; заполненная синяя кнопка — только для основного действия.

Иконки: 20–24px, единая толщина stroke примерно 1.75–2px, скруглённые окончания, одинаковый оптический вес. Для кнопок без текста обязательны accessible name и при необходимости tooltip. Набор на `09_icons.png` — визуальный образец, а не готовый спрайт. Воссоздай нужные иконки настоящими SVG. Не превращай их в растровые вырезки.

## 6. Изображения — обязательная отдельная работа

Изображения должны соответствовать настоящим тайтлам и иметь достаточное разрешение. Не подменяй аниме случайными фотографиями, градиентными прямоугольниками или общими картинками «в стиле аниме». Не используй целые изображения интерфейса из архива как баннеры приложения.

Собери отдельные poster/backdrop/episode/avatar assets. Предпочтительно загрузить подходящие разрешённые для проекта изображения в локальную папку assets, чтобы runtime не зависел от нестабильного hotlink. Для каждого изображения сохрани источник в ASSET_SOURCES.md. Если внешняя загрузка недоступна, используй предоставленные пользовательские ассеты либо конкретно перечисли недостающие. Не утверждай, что все обложки настоящие и доступны, если это не проверено.

Для кадра эпизода не выдумывай соответствие конкретному номеру серии: если точный кадр не найден, используй artwork тайтла с нейтральным оформлением. Рейтинги/даты на референсах не копируй как проверенные факты. Каталог может хранить явно обозначенные редакционные демонстрационные данные. Не выводи фиктивные 50 найденных аниме, если в данных 18.

Правила размеров:

- Постер: фиксированная пропорция **2:3**. `aspect-ratio: 2 / 3`, width 100%, `object-fit: cover`. Лица и ключевой сюжетный объект сохраняй через индивидуальный object-position.
- Кадр серии и карточка продолжения: **16:9**.
- Видео: **16:9 контейнер**, но сам `<video>` — `object-fit: contain`, чтобы не отрезать исходный кадр.
- Аватар: **1:1**, круглый, `object-fit: cover`.
- Баннер списка: примерно **2.4:1**, на телефоне можно **2:1**.
- Hero artwork: отдельный crop для wide и mobile, если композиция требует; не растягивай маленькую портретную картинку на весь широкий экран.

Запрещены растянутые изображения, случайная фиксированная высота карточек разных размеров, огромные пустые рамки и вылезание изображения из контейнера. Не задавай одновременно произвольные width и height, нарушающие пропорции.

Укажи intrinsic width/height или aspect-ratio заранее для предотвращения layout shift. Для второстепенных изображений — lazy loading и async decoding. Hero загружай приоритетно, но только один активный hero, не все скрытые слайды. Используй srcset/sizes или подготовленные варианты размера при разумной необходимости. Ориентиры исходников: постер 400–600px по ширине, кадр 640–960px, backdrop 1600–1920px; не отдавай многомегабайтные 4K-изображения каждой маленькой карточке.

Предусмотри аккуратный fallback при onError, без бесконечной повторной загрузки. Ошибка внешнего ассета не должна ломать сетку. Alt для содержательных обложек — название тайтла; декоративные изображения — пустой alt. Проверяй фактические скачанные файлы, HTTP status, размеры и соответствие названию.

## 7. Адаптивность: не просто уменьшенная desktop-версия

Реализуй mobile-first и проверь ширины **360, 390, 430, 768, 1024, 1280, 1440, 1920px**. Отдельно проверь телефон в landscape и увеличение текста/масштаба. Основные контрольные скриншоты: 390x844 и 1440x1000. Для video fullscreen допускается отдельное поведение платформы.

### Навигация

- Desktop: общий header 72–76px с логотипом, четырьмя разделами, поиском, уведомлениями и профилем.
- Tablet: компактный header; при нехватке места поиск становится кнопкой, текстовая навигация сокращается до реального допустимого числа элементов.
- Phone: header около 56–60px, логотип Anikai, поиск, профиль. Нижняя навигация из четырёх пунктов: Главная, Каталог, Расписание, Коллекция. Подпись + иконка + явное active state.
- Учти safe-area-inset-bottom и добавь content bottom padding, чтобы нижняя навигация не перекрывала последние карточки/кнопки. При открытом fullscreen-плеере и необходимости landscape убирай мешающую навигацию.

### Сетки

- Постеры: 2 колонки на узком телефоне; 3 на небольшом планшете, если ширина карточки достаточна; 4 на tablet; 5–6 desktop. Каталог с desktop sidebar может иметь на одну колонку меньше. Не навязывай шесть колонок ширине 1024px.
- Gaps: 12px phone, 16px tablet, 20–24px desktop.
- Карточка не должна становиться слишком узкой ради числа колонок. Длинное русское название допускает две/три строки по осмысленному правилу; не режь все названия после десяти букв.
- Продолжить просмотр: 3 карточки desktop; на phone аккуратная горизонтальная полоса с одной полной карточкой и частью следующей либо вертикальный список. Если выбираешь горизонтальную полосу, размеры задавай внутри компонента; сама страница не должна иметь horizontal overflow. Touch scroll и scroll-snap работают без hover.
- Фильтры каталога: sidebar desktop, кнопка «Фильтры» и bottom sheet/dialog на phone. Внутри мобильного sheet есть «Показать N аниме» и «Сбросить», контент прокручивается, footer доступен.

### Hero

- Desktop: artwork справа, текст слева, защита читаемости градиентом/нейтральной подложкой. Высота примерно 340–420px после сравнения с референсом.
- Mobile: artwork сверху/фоном верхнего участка, текст и действия ниже. Высота зависит от содержимого; не фиксируй 400px, если текст не помещается. Кнопки помещаются и не перекрывают лицо персонажа.
- Не показывай гигантский портрет, который выталкивает действия за экран. Не обрезай важный текст с помощью overflow hidden ради визуальной похожести.

### Внутренние страницы

- Страница аниме: постер + информация на desktop; компактный постер и информация либо арт сверху на phone. Таблица метаданных не ломает ширину. Вкладки при необходимости прокручиваются внутри своей полосы.
- Плеер: video + episodes sidebar desktop; на phone video сверху, затем кнопки и список серий. Не сжимай sidebar в 80px рядом с видео. В landscape полезно дать видео больше места.
- Расписание: sidebar ожиданий на desktop, на phone идёт ниже основного расписания; day-strip имеет локальный горизонтальный скролл, времена читаемы, кнопки помещаются.
- Профиль: две колонки desktop, одна phone. Редактирование — доступный modal/bottom sheet.
- Настройки: sidebar desktop, компактный selector/tab navigation phone; длинные подписи и toggles не накладываются. На узком экране поле может переноситься под подпись.

Не маскируй ошибки глобальным `overflow-x: hidden`: найди конкретный переполняющий элемент. Для grid/flex детей, где нужно, используй min-width: 0. Не используй viewport width вместо ширины контейнера в обычных карточках.

## 8. Страницы и обязательные взаимодействия

### 8.1 Главная

Референс `01_home.png`: hero Дандадан, подборки, продолжение просмотра, популярные тайтлы.

- «Смотреть» открывает корректную серию/плеер; «В коллекцию» меняет реальное локальное состояние, и это сразу отражается на других страницах.
- «Трейлер» открывает работающий источник, если он действительно есть. При отсутствии не показывай активную пустую кнопку.
- Hero prev/next меняют тайтл/арт/метаданные. По умолчанию без навязчивого autoplay. Если автопереключение есть — пауза при фокусе/hover и reduced motion.
- «Для тебя», «Популярное», «Новые серии» изменяют содержимое. Простая рекомендация по любимым жанрам/сохранённым тайтлам достаточна; не обещай AI-рекомендации, которых нет.
- «Случайное аниме» выбирает существующий тайтл и открывает его страницу. Нет случайных несуществующих URL.
- Если истории ещё нет, блок продолжения просмотра скрывается или показывает спокойный полезный empty state. Не заполняй историю фиктивными просмотрами от имени пользователя.

### 8.2 Каталог

Референс `02_catalog.png`.

- Поиск по русскому/английскому названию и алиасам; игнорирование регистра и лишних пробелов.
- Фильтры жанра, периода, формата и статуса, понятный multi-select. Правила пересечения выбранных фильтров последовательные.
- Сортировка меняет порядок, pagination — реальные данные, счётчик — фактическое количество результатов.
- Изменение фильтра сбрасывает страницу на первую; все состояния синхронизированы с URL.
- «Сбросить» действительно очищает критерии. Empty state предлагает сброс/изменение поиска.
- Hover-overlay улучшает desktop, но основное действие доступно touch и keyboard.
- Карточка открывает тайтл, плюс меняет коллекцию без непреднамеренного перехода. Не вкладывай интерактивную кнопку внутрь другой интерактивной кнопки/ссылки.

### 8.3 Поиск из header

- Desktop — поле/панель результатов; mobile — полноэкранный dialog или удобный sheet с autofocus.
- Есть ввод, очистка, результаты, empty state, Enter, выбор стрелками там, где это уместно, Escape и возврат фокуса.
- Поиск не требует серверного запроса. Отображаются обложка, название и год.
- Поиск может перейти в полный каталог с сохранённым query.

### 8.4 Расписание

Референс `03_schedule.png` — только пример структуры, даты и времена не являются настоящим расписанием.

- Выбор дня переключает события; «Только из коллекции» действительно фильтрует.
- Храни даты как ISO, показывай в выбранном часовом поясе, по умолчанию Europe/Moscow. Дни недели вычисляй, а не записывай независимо от даты.
- В demo-режиме показывай небольшую понятную подпись «Пример расписания». Не выдавай вымышленные релизы за официальные.
- «Напомнить» создаёт локальную отметку и меняет состояние на «Напоминание включено». Покажи события в панели уведомлений при открытом приложении; не обещай push в закрытом браузере, если соответствующая система не реализована.
- Для доступного события «Смотреть» ведёт к существующей серии.
- При смене текущей недели и пустом дне — полезный empty state.

### 8.5 Коллекция и списки

Референс `04_collection.png`.

- Статусы: смотрю, в планах, просмотрено, отложено. Счётчики вычисляются из коллекции.
- Смена статуса, поиск, сортировка, удаление и продолжение просмотра реально работают.
- «Просмотрено» для всего тайтла отмечает соответствующие серии; обратное изменение не должно случайно уничтожать историю и заметки.
- Создание списка: название, необязательное описание, выбор обложки из собственных тайтлов. Редактирование и удаление с понятным подтверждением.
- Добавление и удаление аниме из списка, открытие отдельной страницы списка.
- Пустая коллекция объясняет, как добавить первый тайтл, и ведёт в каталог.
- Предоставь демонстрационную коллекцию как явную опцию в настройках/empty state, не притворяйся, что пользователь уже что-то смотрел.

### 8.6 Страница аниме

Референс `05_anime_detail.png`.

- Название, альтернативное название, год, жанры, формат, краткое описание, число эпизодов и сведения о сезонах по текущим данным.
- «Продолжить» учитывает историю; без истории — «Смотреть с начала».
- «В коллекции» отражает настоящее состояние; выбор сезона меняет эпизоды.
- Серии показывают доступность источника, просмотренные статусы и текущий прогресс.
- «Об аниме» — нормальный информационный блок; «Мои заметки» — локальные заметки; «Похожее» — другие реальные тайтлы с пересечением жанров, без саморекомендации.
- При защите от спойлеров скрывай заголовки/миниатюры будущих серий при наличии потенциальных спойлеров. Это не блокировка просмотра: не делай замок, который запрещает открыть серию, только потому что её ещё не смотрели.
- При отсутствии точных названий серии показывай «Серия N», а не выдуманные сюжетные заголовки.

### 8.7 Плеер

Референс `06_player.png`. Это центральная функция: воспроизведение должно быть настоящим, не анимированным постером.

Используй `<video>` с доступным источником. Свяжи controls с реальным состоянием video: play/pause, volume/mute, currentTime/duration, seek, buffered, ended, loading и error. Не рисуй счётчик времени, который живёт отдельно от медиа.

Если пользователь не предоставил видео аниме, подготовь хотя бы один проверенный небольшой демонстрационный видеофайл из разрешённого открытого источника/пользовательского материала. Явно обозначь возле плеера «Демонстрационное видео», когда источник является демонстрационным, а не эпизодом выбранного аниме. Сохрани происхождение файла и условия использования в ASSET_SOURCES.md. Не подписывай постороннее видео как настоящую серию Фрирен. Сайт должен быть пригоден для замены demo source на реальные пользовательские ссылки в данных без переделки UI.

Лучше локальный стабильный небольшой demo asset, чем зависимость от случайного MP4 URL. Проверь сетевой ответ, формат, MIME и реальное воспроизведение в браузере. Не скачивай большие сезоны и не выдумывай источники. Для тайтлов без mediaSource показывай нормальное состояние «Видео для этой серии пока не добавлено» с навигацией по каталогу; не создавай битую загрузку.

Обязательные возможности:

- Play/pause; перемотка по timeline; назад/вперёд 10 секунд с ограничением 0..duration.
- Громкость и mute; корректный UI на mobile, где платформенное управление громкостью может отличаться.
- Время current/duration, буферизация, ошибка и повторная загрузка.
- Предыдущая/следующая серия только когда она существует; на границах правильный disabled state.
- Список серий и переключение active episode.
- Сохранение прогресса по animeId+episodeId; восстановление после loadedmetadata с ограничением duration. Near-end просмотр лучше завершать, чем возобновлять за последнюю секунду.
- Запись прогресса раз в несколько секунд, на pause, pagehide/visibilitychange и смене серии; не писать localStorage каждый render.
- Отметка просмотрено при завершении и согласованное пороговое правило около 90–95%, с защитой от случайной перемотки, если нужно.
- Автопереход учитывает настройку и доступность источника следующей серии; на последней серии не зацикливает сезон.
- Автоплей со звуком не форсировать. Обрабатывать rejected play() и предлагать кнопку запуска.
- Fullscreen через capability detection. Picture-in-picture только если поддерживается; fallback без сломанной кнопки. Нативный fullscreen на iOS допустим.
- Keyboard shortcuts: Space/K play, arrows ±5/10 секунд, M mute, F fullscreen. Не перехватывать ввод в textarea/input/select/dialog.
- Контролы видимы при pause/focus, появляются при pointer/touch и скрываются аккуратно, не исчезают во время взаимодействия с ползунком/меню.
- Субтитры через настоящие `<track>`/WebVTT, если есть файл. Скрыть выбор несуществующих дорожек.
- Выбор качества/озвучки только когда реальные альтернативные источники есть. Если доступно одно качество — корректно показать одно, а не фиктивные 4K/1080p переключатели.
- Skip opening работает только для эпизодов с конкретным openingStart/openingEnd; никаких универсальных фальшивых таймкодов.
- Режим кино меняет компоновку, не ломая пропорции.
- Локальная заметка привязана к серии и таймкоду; её можно добавить/исправить/удалить.

На маленьком экране убери второстепенные controls в понятное меню, сохрани play, seek и время. Не пытайся уместить 12 иконок в 360px. Настоящие controls должны быть доступны клавиатурой и иметь labels.

### 8.8 Профиль и история

Референс `07_profile.png`.

- Имя, avatar и bio редактируются локально. Default username можно Dmitriy, но данные изменяемы.
- Аватар выбирается из нескольких локальных канонических образов либо загружается пользователем с проверкой файла и уменьшением. Не сохраняй многомегабайтный base64 в localStorage: небольшой сжатый avatar или IndexedDB для blob.
- Метрики вычисляются, не захардкожены. Недавние просмотры и любимое отражают изменения.
- История имеет группировку по датам, переход к серии, поиск/очистку с подтверждением и empty state.
- Если profile visibility не имеет смысла в локальном приложении, не показывай фиктивное «сделать публичным». Предпочти спокойную подпись «Личный профиль» без неработающей настройки.

### 8.9 Настройки

Референс `08_settings.png`.

- Подразделы «Просмотр», «Внешний вид», «Уведомления», «Данные» действительно переключаются; ненужную «Приватность» не добавлять только ради референса.
- Просмотр: предпочтения плеера, автопереход, пропуск opening при наличии метаданных, защита от спойлеров, сохранение прогресса.
- Внешний вид: тёмная тема как основная; если предлагаешь светлую — реализуй её качественно полностью, иначе не показывай недоделанную опцию. Опционально выбор компактности карточек.
- Уведомления: локальные напоминания и настройки панели, без ложного обещания background push.
- Данные: экспорт JSON, импорт валидированного JSON, резервная копия, сброс с подтверждением, загрузка demo collection по явному действию.
- Выбери один честный паттерн сохранения: либо изменения сразу сохраняются и текст об этом понятен, либо изменяемая форма с кнопкой «Сохранить изменения», dirty-state и предупреждением при уходе. Не рисуй кнопку, которая ничего не делает, если всё уже autosaved.

## 9. Локальные данные и типы

Построй ясную модель: Anime, Season, Episode, MediaSource, CollectionEntry, WatchProgress, UserList, EpisodeNote, UserPreferences, UserProfile, ScheduleEvent. Стабильные ids и slugs, не индексы массивов.

Рекомендуемые поля Anime: id, slug, titleRu, titleOriginal/titleEn, aliases, description, genres[], year, format, releaseStatus, poster, backdrop, focalPoint, seasons[]. Episode: id, number, seasonId, title?, duration?, thumbnail, mediaSources[], subtitleTracks[], openingStart?, openingEnd?. MediaSource содержит src, type, label/quality и isDemo.

Разделяй данные каталога и пользовательские данные. Не сохраняй полный каталог при каждом изменении коллекции. Используй ключи с namespace Anikai и версией схемы, например `anikai:user:v1`; схема должна уметь эволюционировать через явную миграцию.

Чтение storage защищено try/catch и валидацией. Повреждённый JSON, quota exceeded, недоступный storage и старые версии не должны приводить к белому экрану. При невозможности persistence продолжай работать в памяти и покажи краткое конкретное сообщение.

Импорт: проверка версии, типов, обязательных полей и разумного размера. Пользователь выбирает понятный режим merge/replace; перед replace подтверждение. Некорректные данные не затирают существующие. Названия/заметки рендерятся как текст, без dangerouslySetInnerHTML. После импорта изменения видны сразу на всех страницах.

Экспорт: нормальный файл `anikai-backup-YYYY-MM-DD.json`, включает нужные пользовательские данные и schemaVersion, без объектов DOM/video, без служебных Blob URL. После восстановления воспроизводится та же коллекция/история/настройки.

Где возможно, синхронизируй открытые вкладки браузера через storage event. UI не должен получать устаревшее состояние при смене страницы. Blob URL освобождай, когда больше не нужен.

## 10. Доступность и взаимодействия

Semantic HTML, правильная иерархия h1/h2, формы с labels, настоящие buttons/links. У interactive элементов видимый focus. Меню и dialogs поддерживают Escape, возврат фокуса, focus trap и корректный background interaction. Не прячь клавиатурный фокус вместе с controls плеера.

Контраст обычного текста ориентир минимум 4.5:1, крупного 3:1; важные иконки/границы controls различимы. На blue button не используй плохо читаемый белый маленький текст. Активность обозначается не только цветом.

Учитывай prefers-reduced-motion. Анимации короткие 150–220ms, мягкие, функциональные. Небольшой hover lift допустим только для устройств с hover; никаких постоянных пульсаций, parallax, случайных пружин и анимации каждого слова.

По touch все основные действия доступны без hover. Не превращай свайпы в единственный способ управления. Кликабельная область иконки больше самой иконки. Scroll при dialog заблокирован корректно и восстановлен после закрытия. Контент не уезжает при появлении scrollbar.

Если добавляешь skeleton, он сохраняет реальные размеры карточки, не мигает искусственно при чтении локального JSON. Toast не закрывает важные кнопки mobile и имеет разумное время жизни. Для удаления допускается Undo, если понятен результат.

## 11. Производительность и статическое размещение

Первый экран не ждёт загрузки всего каталога/видео. Используй route-level code splitting там, где это реально полезно, особенно для плеера. Не подгружай видео всех эпизодов: preload metadata/none по задаче, один активный video.

Локальный поиск не требует сложной инфраструктуры. Debounce при необходимости, но без ощутимого искусственного торможения на малом каталоге. Крупные медиа не должны попадать в JS bundle как огромные data URI. Отдавай файлы отдельно.

Сайт после build запускается обычным static hosting. В README укажи команды dev/build/preview, требования Node, особенности роутинга, где заменить каталог, изображения, видео и субтитры. Не публикуй без отдельной просьбы пользователя. Не добавляй секретные ключи в frontend.

## 12. План реализации и проверки

Работай этапами. После каждого существенного этапа запусти приложение/проверку соответствующего поведения. Исправляй проблемы прежде, чем они распространятся на все страницы.

1. Исследование материалов и проекта, выбор совместимого стека, карта маршрутов и дизайн-токены.
2. Подготовка типизированных данных и отдельных медиа-ассетов; проверка файлов и их источников.
3. AppShell, адаптивная навигация, общий набор компонентов. Сразу открой 390px и 1440px.
4. Главная, каталог и поиск. Проверка фильтров, URL, изображений и длинных названий.
5. Страница аниме, коллекция, списки и сохранение. Проверка после refresh.
6. Настоящий плеер с проверенным источником, прогрессом, заметками, capability fallbacks и mobile layout.
7. Расписание, профиль, история и все подразделы настроек.
8. Полный проход по страницам, accessibility, media fallbacks, ошибки storage, импорт/экспорт.
9. Визуальная полировка по реальным скриншотам, build/typecheck/lint и финальный отчёт.

При наличии browser automation/Playwright используй её. Не утверждай, что тест прошёл, если не запускал. Визуальная проверка обязательна: сделай скриншоты и открой их глазами, автоматические assertions не оценивают композицию.

Не создавай сотни тестов, повторяющих разметку. Нужны небольшие содержательные проверки критических пользовательских сценариев и визуальный осмотр.

### Обязательные сценарии

- Пройти со страницы главной через поиск к аниме и к плееру; переключить существующую серию.
- Добавить тайтл в планы, сменить на смотрю, создать список, поместить тайтл в список, обновить страницу — состояние сохранилось.
- Комбинация нескольких фильтров, сортировка, pagination, сброс, empty state; URL и browser back работают.
- Запустить настоящий demo source, поставить паузу, перемотать, изменить громкость, переключить fullscreen/PiP там, где поддержано.
- Сохранить прогресс, перезагрузить приложение, продолжить примерно с сохранённого времени. Не требуй идеального совпадения десятых секунды.
- Добавить заметку с таймкодом, перейти по таймкоду, исправить и удалить заметку.
- Выбрать день расписания и включить напоминание; фильтр коллекции меняет события.
- Изменить локальный профиль и предпочтения; они отражаются после refresh.
- Export → изменить/очистить через подтверждение → import → данные восстановились. Некорректный импорт отклоняется без потери состояния.
- Проверить отсутствие source, error видео, broken image и пустой результат — никакого белого экрана и сломанной сетки.
- Открыть вложенный маршрут напрямую и обновить, проверить неизвестный slug/episode/404.
- Пройти важные действия клавиатурой; проверить dialog focus/Escape и mobile bottom sheet.

### Визуальная матрица

Скриншоты всех основных страниц на 390x844 и 1440x1000. На 360px, 768px, 1024px, 1920px — дополнительные проверки переломов сетки. Отдельно phone landscape, длинное название, 200% zoom и reduced motion.

На каждом скриншоте оцени: нет ли horizontal overflow страницы; не режутся ли лица; соответствуют ли image ratios; не слишком ли крупные/мелкие заголовки; совпадает ли ритм карточек; не перекрываются ли кнопки; читается ли текст; доступны ли controls; не остаётся ли гигантская пустота; нет ли зелёных UI-акцентов и старого YORU.

Подписывай файлы проверок именами route-width, храни в `docs/screenshots/`. Не засоряй public временными скриншотами. Не применяй размывающие CSS-фильтры к тексту ради похожести на картинку.

## 13. Критерии готовности

Работа завершена, когда:
