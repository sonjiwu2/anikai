# Anikai

Аниме-видеосервис: библиотека аниме, личная коллекция и собственный плеер с сохранением прогресса. Интерфейс — React; для загрузки внешних HLS-потоков нужен небольшой Node-сервер (`server/`).

Стек: React 19, TypeScript 6, Vite 8, React Router 8 (клиентский режим), обычный CSS с токенами, иконки Lucide, шрифт Onest.

## Публичная версия

Сайт: https://sonjiwu2.github.io/anikai/

GitHub Actions автоматически публикует изменения ветки `main` в Pages. Для вложенного пути `/anikai/` настроены адреса ассетов и маршруты через `#`, поэтому прямые ссылки на серии работают после перезагрузки.

Pages не запускает Node-сервер. В этом режиме Rutube и Одноклассники используют официальные встроенные плееры. AniLiberty загружается напрямую через публичный API с CORS. Восемь нарезанных серий «Монолога фармацевта» — самостоятельные MP4 в релизе `library-v1`, воспроизводятся собственным плеером. Файлы не входят в Git из-за лимита размера: чтобы вернуть их локально, скачайте релиз и разместите файлы в `public/media/video/apothecary-diaries/` под именами `s2e01.mp4` … `s2e08.mp4`.

Для своего сервера задайте при сборке `VITE_VIDEO_API_URL` — плеер будет обращаться к нему вместо встроенных плееров. API должен разрешать CORS для домена сайта; обычная локальная сборка использует API того же домена.

## Запуск

Нужен Node.js `^20.19.0` или `>=22.12.0` (требование Vite 8).

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # проверка типов + сборка в dist/
npm run preview    # собранная версия на http://localhost:4173
npm start          # собранная версия + сервер потоков на http://127.0.0.1:4173
npm run lint
npm run typecheck
```

## Каталог: как добавить или заменить аниме

Каталог собирается из двух частей.

1. **Скачиваемые данные** — `src/data/generated/anilist.json` и файлы в `public/media/`. Их создаёт скрипт:

   ```bash
   npm run assets
   ```

   Он берёт факты и популярность из AniList, названия, даты и кадры серий из Kitsu, русские описания и оценку из Shikimori, складывает изображения в `public/media/` и обновляет `ASSET_SOURCES.md`. Постер берётся из того источника, где он крупнее (Kitsu или AniList). Широкий фон по умолчанию — баннер AniList; пометка `backdrop: 'kitsu'` в `scripts/titles.mjs` переключает тайтл на обложку Kitsu (для неё точка кадрирования задаётся в `KITSU_BACKDROP_FOCUS` в `src/data/catalog.ts`). Кадры серий не увеличиваются, а кадры уже 320 px не используются. Список тайтлов и их идентификаторы AniList по сезонам — в `scripts/titles.mjs`. Скачанное кешируется в `scripts/.cache/`; `npm run assets -- --force` качает всё заново. Для Shikimori нужен `curl` в PATH (в Windows 10+, macOS и Linux он есть).

2. **Редакционные тексты** — массив `EDITORIAL` в `src/data/catalog.ts`: русское название, слоган, короткая аннотация, жанры, названия сезонов, точка кадрирования фона (`focalX`, 0–100).

Чтобы добавить аниме: впишите его в `scripts/titles.mjs`, выполните `npm run assets`, добавьте запись в `EDITORIAL`. Запись без скачанных данных в каталог не попадает.

## Видео: собственный плеер Anikai

Каталог содержит проверенные ссылки на 735 эпизодов и фильмов. Основной источник — канал [Анимач](https://rutube.ru/u/animach/), дополнительные — другие публичные каналы Rutube и API AniLiberty. Таблица покрытия, недостающие серии и все ссылки — в [VIDEO_SOURCES.md](VIDEO_SOURCES.md).

Потоки проигрываются в `<video>` собственным плеером Anikai через `hls.js`: пауза, перемотка, скорость, выбор доступного качества, сохранение позиции, пропуск отмеченного опенинга, заметки и автопереход работают на настоящих сериях. На браузерах без MSE используется встроенная поддержка HLS, если она есть; выбор качества тогда автоматический. В каталоге больше нет подмены серии трейлером Sintel: для отсутствующих видео показывается «Видео не добавлено».

`src/data/generated/video-sources.json` хранит проверенные идентификаторы и происхождение видео. Адреса HLS запрашиваются при просмотре: короткоживущие подписанные ссылки не записываются в каталог. `/api/video/…` проверяет доступ к видео, загружает плейлисты и сегменты и переписывает их адреса для браузера. Используются только перечисленные в каталоге видео и подписанные сервером ссылки на ресурсы источника; произвольные URL не принимаются. Закрытые, платные, удалённые, заблокированные и защищённые DRM видео не подключаются. Параметры потоков AniLiberty сохраняются без изменения.

Обновить источники:

```bash
npm run videos:sync               # поиск и проверка; публичные результаты поиска кешируются
npm run videos:sync -- --force    # обновить метаданные из сети
npm run build
```

После обновления каталога перезапустите сервер. Доступность внешних видео может измениться; сообщение об ошибке позволяет повторить загрузку, а ссылка «Открыть источник» ведёт на исходную страницу.

## Ручная привязка с Rutube и VK Видео

В каталоге нет файлов серий. Серии открываются двумя способами.

**Привязанное видео.** К любой серии можно привязать ссылку на видео с Rutube или VK Видео: кнопка «Привязать видео» под плеером, на месте плеера у серии без видео и на странице аниме. В поле можно вставить сразу несколько ссылок, по одной на строку: первая пойдёт на выбранную серию, остальные — на следующие по порядку, так привязывается целый сезон. Понимаются ссылки вида `rutube.ru/video/<id>/`, `rutube.ru/play/embed/<id>`, `vkvideo.ru/video-1_2`, `vk.com/video-1_2`, `vk.com/video_ext.php?oid=…&id=…&hash=…`.

Видео остаётся на площадке и показывается её собственным встраиваемым плеером, с её рекламой и её качеством. Сайт общается с плеером сообщениями `postMessage` (`src/components/player/EmbedPlayer.tsx`): читает время и состояние, отправляет перемотку и запуск. Поэтому для привязанного видео работают сохранение прогресса и продолжение с места, отметка «просмотрено», автопереход, таймкоды заметок и пропуск опенинга. Ссылки хранятся в данных пользователя (`sources`) и входят в резервную копию.

Ручные привязки сохраняются в браузере и имеют приоритет над общим каталогом. После удаления такой привязки снова используется источник из каталога, если он есть.

Чего встроенный плеер не умеет: управлять качеством, скоростью и субтитрами (это делается в самом плеере площадки), работать с приватными видео Rutube, получать название ролика (API Rutube закрыто для запросов из браузера).

Ручная привязка по-прежнему использует встраиваемый плеер площадки. Автоматически подключённые серии используют собственный плеер Anikai.

## Пропуск опенинга

Кнопка «Отметить опенинг» под плеером открывает форму: начало и конец заставки (время можно взять из плеера кнопкой «Взять текущий момент») и область действия — все серии сезона или только эта. После этого в отмеченном отрезке появляется кнопка «Пропустить опенинг», отрезок виден на шкале, а с настройкой «Пропускать опенинги» плеер перематывает сам. Отметки хранятся в данных пользователя (`openings`). Работает и для локального видео, и для Rutube и VK.

## Собственные файлы, субтитры

Чтобы серии играли из ваших файлов в плеере Anikai, отредактируйте `src/data/catalog.ts`:

- `buildSeasons` в `src/data/catalog.ts` собирает `mediaSources` для каждой серии. Здесь можно задать собственные MP4 или HLS вместо источника из сгенерированного каталога.
- `MediaSource`: `src`, `type` (MIME), `label` и `height` (для выбора качества), `isDemo`. Несколько источников разного `height` дают настоящий переключатель качества; один источник — переключателя нет.
- `SubtitleTrack`: `src` (WebVTT), `lang`, `label`. Без дорожек кнопка субтитров не показывается.
- `openingStart` / `openingEnd` в секундах у серии задают опенинг прямо в каталоге; такая разметка важнее пользовательской.
- Серии без `mediaSources` и без привязанного видео показывают состояние «Видео для этой серии пока не добавлено» с кнопкой привязки. Все отсутствующие эпизоды перечислены в `VIDEO_SOURCES.md`.

Видео и субтитры кладите в `public/media/` или указывайте внешние адреса.

## Данные пользователя

Коллекция, прогресс, списки, заметки, профиль и настройки хранятся в `localStorage` под ключом `anikai:user:v1`. Каталог туда не пишется.

- Модель — `src/types/index.ts`, значения по умолчанию и проверка — `src/lib/userData.ts`, хранилище и действия — `src/lib/store.ts`.
- При чтении данные проверяются. Повреждённая запись не роняет приложение: она сохраняется в `anikai:user:v1:corrupt`, приложение стартует чистым и сообщает об этом.
- Если хранилище недоступно или переполнено, приложение работает в памяти до закрытия вкладки и показывает сообщение.
- Изменения из другой вкладки подхватываются через событие `storage`.
- Версия схемы — `schemaVersion`. Для будущих версий добавляйте шаг в функцию `migrate`.
- Резервная копия (`Настройки → Данные`) — файл `anikai-backup-ГГГГ-ММ-ДД.json`. Импорт проверяет файл и предлагает добавить данные к текущим или заменить их; некорректный файл отклоняется без изменений.
- Пример коллекции загружается только по кнопке — в настройках или из пустой коллекции.

## Размещение

Для просмотра автоматически подключённых серий размещайте проект с Node-сервером:

```bash
npm ci
npm run build
npm start
```

`PORT` задаёт порт (по умолчанию 4173), `HOST` — адрес (по умолчанию `127.0.0.1`; для контейнера или внешнего доступа задайте `0.0.0.0`). Сервер отдаёт `dist/`, поддерживает маршруты React и `/api/video/`. Потоки проходят через сервер, поэтому учитывайте его исходящий трафик и скорость сети.

`npm run dev` и `npm run preview` также включают API потоков через плагин Vite. `vite preview` предназначен для локальной проверки, для публикации используйте `npm start`.

Если отдельно размещать `dist/` на статическом хостинге, направляйте `/api/video/*` на этот Node-сервер через reverse proxy под тем же доменом. Без API автоматически подключённые серии не загрузятся. Маршруты чистые (`/catalog`, `/anime/frieren`), поэтому статический хостинг должен отдавать `index.html` на неизвестные маршруты интерфейса:

- Netlify и Cloudflare Pages: файл `public/_redirects` уже есть.
- Vercel: добавьте rewrite всех путей на `/index.html`.
- nginx: `try_files $uri /index.html;`

Для хостинга без таких правил соберите с адресами через `#`:

```bash
VITE_ROUTER_MODE=hash npm run build
```

Сборка рассчитана на размещение в корне домена: пути к медиа начинаются с `/media/`.

## Проверки

Проверки новой интеграции:

```bash
npm run test:video         # соответствие сезонов и серий, фильтр реакций, API и подписи ссылок
npx playwright install chromium
npm start                 # в отдельном терминале после npm run build
npm run test:native        # живой Rutube + AniLiberty, управление, прогресс, автопереход, мобильная ширина
```

Для `test:native` адрес задаётся `ANIKAI_URL`, путь к установленному Chromium — `ANIKAI_BROWSER_PATH`. Живая проверка требует доступа к источникам. Скриншоты сохраняются в `docs/screenshots/native-*.png`.

Сценарии написаны на Python Playwright и работают по запущенному серверу:

```bash
py -m pip install playwright
py -m playwright install chromium
npm run dev
py tests/scenarios.py                    # все 15 сценариев
py tests/scenarios.py playback notes     # выборочно
```

Другой адрес задаётся переменной `ANIKAI_URL` (например, `http://localhost:4173` для собранной версии). В сценарии `embeds` плееры Rutube и VK подменяются заглушками с тем же протоколом сообщений, поэтому он не зависит от сети и рекламы.

Вспомогательные скрипты:

- `node scripts/contrast.mjs` — контраст используемых цветовых пар.
- `scripts/screenshots.js` — матрица скриншотов в `docs/screenshots/` (запускается через `playwright-cli run-code`).
- `node scripts/contact-sheet.mjs` — контактные листы постеров и фонов.

## Клавиши в плеере

`Пробел` / `K` — пауза, `←` `→` — 5 секунд, `J` `L` — 10 секунд, `↑` `↓` — громкость (фокус в плеере), `M` — звук, `F` — во весь экран, `C` — субтитры. В полях ввода, диалогах и меню клавиши не перехватываются.

## Что стоит знать

- **Изображения — чужая собственность.** Постеры, фоны и кадры принадлежат правообладателям и скачаны для локальной демонстрации. Перед публикацией сайта замените их или получите разрешение. Подробности — в `ASSET_SOURCES.md`.
- **Видео загружается из внешних источников.** В проекте хранятся ссылки, а не файлы аниме. Проверены живое воспроизведение Rutube и AniLiberty в собственном плеере, управление качеством и скоростью, продолжение, автопереход и мобильная ширина. Доступность источников зависит от площадки.
- **Оценки и популярность — реальные данные** на дату сборки: оценка Shikimori на карточках, оценка AniList и число зрителей AniList на странице аниме. Сами они не обновляются; обновить — `npm run assets`.
- **Трейлеры не показываются.** Скрипт подтверждает ссылку через YouTube; на машине, где собирались данные, YouTube был недоступен, поэтому ни одна ссылка не подтверждена и кнопка «Трейлер» скрыта. Перезапуск `npm run assets` при доступном YouTube её вернёт.
- **Названия серий — на английском** (официальные названия из Kitsu и AniList), русских названий серий в открытых источниках не нашлось. У части серий нет названия или кадра — тогда показывается «Серия N» и фон тайтла.
- **Данные только в этом браузере.** Синхронизации между устройствами и аккаунтов нет. Напоминания работают, пока сайт открыт; push-уведомлений нет.
- **Светлой темы нет** — только тёмная.
- **Проверено в Chromium** (Playwright). В Safari, Firefox и на реальных телефонах проект не запускался; вариант сборки с `VITE_ROUTER_MODE=hash` не проверялся.
- **Каталог — снимок на дату сборки** (см. `ASSET_SOURCES.md`): оценки и статусы сами не обновляются.
